# 자기소개서

## 멈춤에서 찾은 새로운 동력: 조건을 통제하여 시스템을 견고하게 만드는 백엔드 개발자

2026년 7월 13일 저녁, 광안리 해변에서 달리기를 멈췄습니다. 두 번째 구간에 들어서자마자 숨이 차오르고 갈비뼈까지 아팠습니다. 속도를 낮춰도 호흡이 돌아오지 않아 결국 멈춰 섰습니다. 걸어서 집에 오는 길, "괜히 멈춘 건가?" 하는 아쉬움과 함께, 힘들게 만든 달리기 루틴이 끊길까 봐 불안했습니다. 하지만 좌절하는 대신 상황을 객관적으로 분석하기 시작했습니다. 그날의 조건들을 짚어보니 긴 바지, 수면 부족, 늦고 무거운 저녁 식사가 원인이었습니다. 무리해서 달리는 대신 하루를 온전히 쉬며 컨디션을 회복했고, 다음 달리기 전에는 반바지를 입고, 충분히 자고, 저녁을 가볍게 먹는 것으로 조건을 바꿨습니다. 이틀 뒤인 7월 15일 저녁, 저는 다시 나가 천천히 달렸고 결국 완주해 냈습니다. 이 경험은 제게 **자기조절력**의 진정한 의미를 깨닫게 해주었습니다. 문제가 생겼을 때 스스로를 탓하기보다, 내가 바꿀 수 있는 통제 가능한 '조건'을 찾아 조율하면 결국 목표에 도달할 수 있다는 확신을 얻었습니다.

문제를 해결하는 이 방식은 개발 실무에서도 그대로 이어졌습니다. 다이어리 앱의 계정 삭제 기능을 구현할 때의 일입니다. 계정을 삭제해도 다른 브라우저에서 여전히 로그인이 되는 치명적인 버그가 발생했습니다. 처음엔 코드를 의심해 수정 요청을 나누어 보내보기도 했지만, 자동화 테스트를 통과했음에도 콘솔 창에는 여전히 빨간 줄이 가득했습니다. 답답함 속에서 저는 달리기 때처럼 '조건'을 하나씩 통제하며 직접 딥다이브하기로 마음먹었습니다. 끈질긴 디버깅 끝에, 실제 데이터가 아닌 로컬 스토리지에만 삭제 표시(안티패턴)를 남기고 있다는 진짜 원인을 찾아냈습니다. 문제를 파악한 후, 클라우드 삭제 → 마커 기록 → 세션 종료라는 정확한 실행 순서를 명시하여 버그를 완벽히 해결했습니다. 예전의 저였다면 뜻대로 풀리지 않는 문제 앞에서 쉽게 좌절했을지 모릅니다. 하지만 이제는 낯선 오류 앞에서도 도망치지 않고, 당장 내가 바꿀 수 있는 코드와 로직의 조건부터 찾아 하나씩 풀어나가는 **자기동기력**을 갖추게 되었습니다.

나아가 저는 개인의 문제 해결을 넘어, 팀 전체의 효율과 시스템의 지속 가능성을 고민하는 개발자로 성장했습니다. 전자결재 연동 업무를 담당할 당시, 명확한 매뉴얼 없이 개인의 경험에만 의존하다 보니 팀 내에 작업 병목과 소통 착오가 잦았습니다. 저는 특정 인원에 대한 의존성을 낮추기 위해 API 호출 순서, 에러 코드별 대응 가이드, 단계별 테스트 시나리오를 상세히 문서화하여 위키에 배포했습니다. 그 결과 누구나 쉽게 전자결재를 연동하고 검증할 수 있게 되어 부서 간 소통 비용을 획기적으로 줄일 수 있었습니다. 동료들의 피드백을 수용하고 해결 과정을 자산화하여 팀의 반복 비용을 줄이는 **대인관계력**은 제 중요한 무기가 되었습니다.

데이터 흐름을 추적해 정합성을 지키고 시스템의 신뢰를 높여왔습니다. 비효율적인 쿼리를 분석해 응답 시간을 3분에서 10초, 5분에서 5초 이내로 단축했던 ERP 쿼리 튜닝 경험처럼, 저는 눈앞의 문제를 집요하게 파고들어 구조적 한계를 개선합니다. 일상의 약속을 지키는 꾸준함, 환경을 바꾸어 재도전하는 회복탄력성, 그리고 해결 과정을 지식으로 나누어 팀의 성장을 돕는 태도를 바탕으로, 어떠한 오류 앞에서도 멈추지 않고 시스템을 단단하게 지탱하는 개발자가 되겠습니다.
